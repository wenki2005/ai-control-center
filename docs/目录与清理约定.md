# 目录与清理约定

更新日期：2026-11-08。

## 日常放置

- 源码留在 src、public、plugins、desktop、remote-client；不要混入临时备份和安装器。
- 现行操作说明放 docs；带日期的故障、试验、方案和交付记录按需要移入 docs/history，保留链接和原始证据。
- 运行数据、个人配置和恢复审计放 runtime；一次性整理材料放 runtime/material-cleanup，不和可分发源码混放。
- desktop/dist 保留当前桌面入口；remote-client/dist 保留当前下载客户端。打包试验目录和被替代安装器经核对后删除。
- 干净源码包统一放 runtime/distribution。保留最新 ZIP、文件清单、构建元数据与本次验收副本；新版本验收通过后再清除旧副本。

## 清理的核对顺序

1. 查看未提交改动、运行进程、当前客户端版本及启动和下载路径。
2. 对文档与维护脚本先做带清单的备份。历史唯一材料归档，不按日期直接丢弃。
3. 删除构建产物前，确认绝对路径在本项目的明确构建目录内，且没有运行进程使用；拒绝重解析点或目录链接。
4. 安装包和解压测试目录属于可重建产物，清理前记录文件哈希与大小。该清单不包含安装包本体，不能据此恢复同一二进制。
5. 核对保留程序的哈希、实际下载入口和服务状态；修复移动文档产生的本地链接。

## 需要另行处理的内容

数据库、个人记忆、聊天与附件、引擎 home、当前固定会话、授权、备份与未知业务结果，不属于安装包清理范围。会话归档必须沿既有保留策略。日志可能仍由进程写入，不能仅因名字像临时文件就删除。

空目录或来源不明的测试资料，先证明来源和未被引用；无法确定时保留。本规则不是定时删除任务。
