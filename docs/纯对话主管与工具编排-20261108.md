# 纯对话主管与工具编排

本轮按照用户要求，将查询会话、调用工具与执行编排从对话主管下移，复用原来的持久 DSH 派发器。没有再增加一层主管。

```text
用户原话 → 对话主管：自然接话、交接目标、结束本轮
                       ↓
               工具编排器（原派发器）
                 ├─ 固定工作池：独立工作使用空闲席
                 ├─ 原生或特殊会话：点名、引用或同任务续接
                 ├─ 手机专用会话：手机独占队列
                 ├─ 远端会话：核对设备及实际授权
                 └─ 窗口观察会话：核对设备、窗口与最新摘要
                       ↓
                 真实结果 → 当前人设整理 → QQ／聊天
```

## 角色边界

当前 DSH 对话主管的模型工具清单为空，执行守卫也拒绝工具调用。它保留人设、共享记忆、用户原话、当前时间、引用和观察摘要；需要更多资料时交给编排器。既有已装载记忆可直接用于交流，无需为了工具分层把已知事实重新查一遍。

编排器只暴露有明确入口的中枢工具，包括会话查询、原会话消息、任务补充、记忆检索、手机浏览提交、共享窗口状态、绘图和歌声提交。它没有通用桌面、Shell 或任意 HTTP 执行入口；实际操作由目标工作会话及原生权限执行。Codex 直连与自动修复各自的绑定和工具保持独立。

对话主管用简短协议交接，不负责原生目录枚举。枚举、候选选择和续接校验发生在编排器以下。原生会话明确时继续原身份，忙或失效时保留目标；同名时提供候选。查询原会话不会另外创建一个普通工作席代查。

## 可靠性

- 查询有真实接口返回才形成查询结果；缺证据的文字不能算工具成功。
- 提交后台工作与完成工作分别记录，QQ 入队与平台确认分别记录。
- 传输中断保留未知结果，不能据旧的成功查询声称新提交已成功，也不自动重复有副作用的请求。
- 普通工作提交后编排器结束本轮，不等待完整执行；主管可以继续下一轮交流。
- 结果继续使用已有的角色整理和发送账本，同一任务不再生成额外重复回执。
- 共享选择、停止、审批和远端权限继续沿用已有确认机制。

## 性能与限制

本轮减少的是前台的工具往返、会话查找和等待长任务。上游模型的首字延迟和生成时间仍会影响回复速度；不能承诺固定秒数。复杂查询现在由编排器处理，仍需要相应的工具时间。编排器本身是一个持久会话，长工作必须交给工作席或后台能力，避免占住编排会话。
