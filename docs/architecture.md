# 架构与能力边界

## 边界与技术

系统为本机Agent编排层。Node.js24提供HTTP、SSE、引擎进程及定时工作；SQLite使用WAL保存可追踪状态；文件归档保存哈希与来源。DSH经认证HTTP/RPC/WebSocket执行，Codex经app-server执行。QQ通过本机OneBot接入。

## 职责划分

Hub协调任务；routing负责引擎政策、固定席位和同任务交接；lifecycle/director-continuity负责主管接续；reports/narrator负责结果整理；qq-delivery-ledger与Store负责发送事实；knowledge负责档案及分层检索；observability负责连接证据、用量、自动修复与运行采样。

同一任务优先保持原上下文，独立任务使用空闲席位。手机等共享资源串行。对话主管和执行工作分开，使工作排队时对话仍可处理，但同一主管回合本身仍有引擎串行约束。

## 可靠性约束

引擎终态、结果整理、消息投递是三个不同状态。必须有可核验回执才报告送达。重启、超时和未知副作用不通过盲目重放解决。主管换代保留原任务和待选项；审批需求交用户判断。退出和停止要求单独确认。

自动修复通过基线核对、独立回归、真实恢复证据与版本指纹验收；不能只凭诊断文字或服务在线认定修复。失败有有限重试；不能处理的权限或外部条件保留明确阻碍。

手动重载和后台升级共用 `lifecycle/release.reloadActivity`，统一核对任务、审批、桌面操作、主动消息、回顾、汇报、QQ发送、绘图、邮件及本机/远端共享。重载宽限期结束前再次检查；出现新活动就延期并保留重载请求，关服时取消未执行的重载定时器。

指定原生会话的查询或联系直接由主管连接，是工作池派单的明确例外。远端助手保留独立的设备授权和原生接收/完成回执；设备接收不是工作完成。本机工作池、手机排他队列及 Codex 直连/自动修复绑定不因此合并。

## 能力与限制

屏幕共享必须由使用者选择窗口；采样分析不等于实时视频。手机控制需要已连接并授权的设备。新闻、链接、邮件、图像生成和服务器监控依赖各自可用的后端；没有配置就不能宣称已经接通。记忆记录有来源也仍可能检索不准，人物表达效果不能由单元测试完全证明。

目前适合个人使用和技术演示；交付其他机器时需要额外配置和验收。后续重点是持续运行证据、安装配置体验和减少核心协调耦合，不以新增功能数量代替稳定性。

## 轻量化职责边界

`observability/event-journal.mjs`只管理本进程新产生的流式日志：仅当适配器明确报告累计快照、原生会话/请求及runVersion一致时，在1秒窗口合并。普通正文、重试、用量、审批、副作用和最终结果保持独立；不修改进程启动前的历史事件。createdAt是首次事件时间，coalesced.lastSeenAt是最后活动时间。SSE继续作为重新读取通知，任务事件读取不依赖每个token递增事件ID。

`http/task-read-view.mjs`独立提供任务摘要，默认compact包含40条近期任务和全部活动任务，历史通过`GET /api/tasks/history?limit=40&before=<cursor>`读取；原完整状态入口保留。读取不提交或恢复工作。任务停止HTTP入口要求`confirmed:true`，与页面独立确认对应。

`adapters/terminal-release.mjs`在辅助服务处理完真实终态后确认释放适配器记录。活动回合、未解决审批仍由适配器保护，不按TTL清空；超时和未知结果不能假装收到终态。`knowledge/stable-document.mjs`按内容哈希避免相同文档反复写入，真实人设或记忆变化仍更新版本。

`lifecycle/resource-recovery.mjs`将预算保护与业务结果分开。显式绘图预算核对必须匹配提交时记录的后端来源，并取得有效空闲队列；来源缺失/变化、断线或并发活动继续保留保护。释放预算不改未知业务终态，冷恢复必须取得新证据，不使用旧的空闲观察跳过保护。维护页分别展示磁盘代码和已加载版本；旧进程缺入口时需要操作者正常退出再打开，不能通过改历史终态绕过保护。

用户也可明确放弃一笔历史未知绘图的恢复。GET `/api/local-resources/drawings/:id/abandon-recovery`预览精确版本；POST同路径要求expectedVersion、confirmed:true和绑定该目标的authorization（id、source、targetId、confirmation）。`scripts/abandon-drawing-recovery.mjs`提供相同规则的操作员入口，默认只读预览；--apply须同时有--confirmed、--expected-version、--authorization-file。该路径持久记录用户决策，只让匹配原版本的该作业不再恢复预算，不改uncertain业务结果或remoteId；其他未知作业仍保护，活动或版本冲突拒绝。CLI不控制服务，也不会释放旧运行进程中的内存预算。授权文件由操作者提供，不在分发包中。
