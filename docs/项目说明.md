# AI 中枢项目说明

更新日期：2026-11-08。

## 1. 项目定位

AI 中枢把持续交流、任务派发、执行引擎、共用记忆、文件管理和消息回传组合成一个本地系统。它自身协调工具与会话，模型推理和实际工作由已接入的 DSH、Codex 等引擎完成。

系统支持网页、Windows 桌面入口与 QQ；另一台电脑可安装陪伴助手接入。角色姓名、头像、称呼、主题色和语音随人设切换，用户事实与历史记忆共用。

## 2. 核心架构

| 层级 | 主要职责 | 持久状态 |
| --- | --- | --- |
| 接入与界面 | 接收原话、引用、附件、审批和设备状态 | 入站消息、引用与附件来源 |
| 对话主管 | 交流、理解追问、查询记忆、整理工作结果 | 原生主管会话、人设文档版本 |
| 派发与工作池 | 尊重引擎选择、分配空闲席位、保持同任务续接 | 任务关联、原会话与原生请求身份 |
| 执行适配器 | 接收真实引擎事件、处理审批、取消与重连 | 请求标识、完成或失败证据 |
| 投递与文件 | 分段、发送、平台回执、文件对账与归档 | SQLite 收发账本与文件索引 |
| 维护与恢复 | 错误分类、有限重试、独立修复验证、轻量采样 | 修复工单、验证结果与审计 |

普通对话由持久主管处理；任务按需交给持久派发器。DSH 有三个普通固定工作席，独立任务可并行，同一原生会话的回合仍需协调。手机和共享设备沿各自独占资源规则运行。用户指定的会话或引擎优先，追问和重试保留前序结果与错误。

Codex 直连窗口和自动修复窗口是独立绑定。中枢重载不应重放 DSH 已接受的原话；符合条件的请求重启后只跟随原请求。尚未确认接收、待审批、屏幕共享、发送和语音等活动具有各自的保护条件。

## 3. 记忆、角色和上下文

记忆使用本地 SQLite 与文件文档，按确认事实、交流经历、时间线、任务成果和反思组织。事实应有来源；助手推测、角色背景与测试材料不能当成用户经历。更正保留历史，撤回内容及修复通信按已有排除规则处理。

查询采用关键词及可选的本地 Qwen 向量检索，语义服务不可用时回退关键词。系统按相关性读取有限内容，通过版本化文档和原生持续会话保持连贯，避免每次拼入完整历史。检索命中并不证明事实正确，仍需核对来源、实际发生时间及最新更正。

角色卡记录人物身份、说话风格、称呼、示例与展示配置。共用记忆独立保存；切换角色时称呼、汇报与主题应同步变化。人物示例是表达参考，不能写入用户事实库。

## 4. 能力与依赖

| 能力 | 实现范围 | 需要另行接入的组件 |
| --- | --- | --- |
| 对话与任务 | 持久会话、三席 DSH 工作池、原任务追问、引擎选择 | 本人的 DSH / Codex 安装与授权 |
| QQ 与文件 | 引用、附件、分段、平台回执、成果文件库 | 兼容的 OneBot / QQ 服务及账户 |
| 资料与记忆 | 文档归档、来源、时间线、可选语义检索 | 文档解析所需 Python 包；可选本地向量模型 |
| 主动陪伴 | 主动交流、日记、每日总结、Token 日报、新闻与邮件摘要 | 模型、联网工具和对应账户；按设置启用 |
| 看屏与设备 | 用户选屏、专属观察会话、设备状态与远端任务通道 | 共享客户端、真实设备权限和控制驱动 |
| 桌面工具 | agent-desktop 状态查询及原生执行会话中的工具接入 | 单独安装 agent-desktop；操作仍需核验结果 |
| 语音与绘图 | 角色音色、网页语音回放、本地与专用绘图通道、唱歌接口 | 本地合成、绘图、唱歌服务与模型 |
| 服务器监督 | 容量、流量与配置到期提醒，异常按设置汇报 | 服务器指标接口及本人授权 |

这些是程序提供的接入能力，不表示另一台机器无需安装就能全部工作。远端离线、账户未授权及未完成的实机操作必须保留为待验证。

agent-desktop 已在本机完成原主管的真实状态查询：平台、版本与辅助功能权限成功返回。它的全部桌面操作没有因此被一并验收；完整原生 MCP 工具也尚未统一进入中枢所有设备租约路径。

## 5. 消息送达与恢复

发送账本区分入队、发送中、平台确认、结果未知和失败。分段保留关联与次序；已确认的段不重复发送，未知副作用先查证据。平台确认表示平台接受，不表示接收者已读。

错误策略区分临时限流、额度耗尽、认证、目标失效、请求格式、冲突和负载过大。重试遵守 Retry-After、上限与原任务身份；未知邮件、QQ 或桌面操作不能直接重放。自动修复应执行恢复或代码修改，再独立验证；无法验证时保留具体阻碍和历史。

## 6. 本机维护与新机器部署

本机服务默认端口为 3188，DSH 默认端口为 3080。已有实例应沿安全入口重载，不再开第二个实例抢端口或 QQ 所有权。先阅读项目 AGENTS.md，核对活动任务、共享与未提交工作。

干净源码分发包需要 Node.js 24+。解压到新目录，安装 npm 依赖，运行语法检查和基础测试，再由启动脚本生成独立空配置。外部引擎、QQ、模型、邮箱与远端设备由接收方自行配置，详见同包 README 与部署说明。包内不提供预授权账号。

本机桌面程序、远端陪伴助手和干净源码包是三个不同产物。前两者为各自客户端入口，源码包为中枢服务与通用接入代码，不等同于把整台电脑打包迁移。

## 7. 目录与发布材料

开发源码在 src、public、plugins；桌面与远端客户端在 desktop、remote-client；维护脚本、测试和评估分别在 scripts、test、eval。现行说明放 docs，阶段性方案、故障和验收资料放 docs/history。

runtime 属于当前实例的私有工作区，包含配置、数据库、成果、备份和恢复审计。清洁发布按白名单取文件，排除整个 runtime、个人角色和图片、密钥、模型、依赖及日志。只在 runtime/distribution 保存本次发布与验收副本，旧构建按清理记录淘汰。

## 8. 当前完成度与限制

系统已经具有本地闭环和多项真实验收证据，仍是面向个人使用、需配置外部环境的工程项目。主管和服务入口仍承担较多协调职责；外部模型容量、网络抖动、QQ 回执丢失、远端离线和界面可访问性都会影响运行。

配置中的上下文上限不能扩充提供商实际支持的模型窗口。人设示例也不能保证每次回复都自然或事实完整。短期测试、HTTP 在线与单轮成功均不能代替长期可用性验证。

后续适合继续改进的方向是首次安装检查、模型及驱动能力自动发现、统一桌面资源协调、真实运行质量评估与故障回归。每项应有具体证据和验收边界，避免仅增加重复提示和兼容分支。
